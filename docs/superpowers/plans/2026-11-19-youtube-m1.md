- **Date:** 2026-11-19
- **Status:** M1 implemented and verified 2026-11-20 (offline suite, live YouTube helper, live Navidrome/GStreamer)
- **Scope:** one milestone (M1): YouTube Music search, playback, lyrics, and
  running without Navidrome for those flows.
- **Decision owner:** samvivan
- **Related:** [`docs/ARCHITECTURE.md`](../../ARCHITECTURE.md),
  [`docs/CONVENTIONS.md`](../../CONVENTIONS.md),
  [`docs/superpowers/plans/2026-11-09-myuzik-v1.md`](2026-11-09-myuzik-v1.md)

## 1. Summary

Add YouTube Music as an optional second music source while keeping Navidrome.
M1 delivers:

1. Search YouTube Music from the existing Search page, in a separate
   **YOUTUBE MUSIC** section.
2. Play a result by resolving it with `yt-dlp`, buffering the audio to a local
   cache file, and handing that file to the existing GStreamer `playbin`.
   Clicking a result queues that song's YouTube Music radio/watch playlist, not
   the search page.
3. Cover art from the YouTube thumbnail, lyrics from LRCLIB, and the existing
   overlay/MPRIS/queue behaviour.
4. A usable app without a Navidrome server: Search, Now Playing, Settings,
   lyrics and the overlay work; library-only routes show a connect prompt.

The design is deliberately **buffer-first**. Both reference applications were
studied; one buffers, one streams directly. Buffer-first costs a short start
delay and some disk, but gives reliable seeking, duration, MPRIS position and
replay, which Myuzik's lyrics overlay and keyboard controls need.

YouTube extraction is unofficial and can break. The user accepted that risk.
M1 exposes no download/export feature and does not redistribute audio.

## 2. Research

### 2.1 Sung (`/home/samvivan/Downloads/Sung`)

Sung is a C++20/Qt 6/QML player, MIT licensed (`LICENSE`), with a Python
one-shot helper (`helper/catalog.py`, 486 lines) and a large Qt backend
(`src/backend.cpp`, 2,938 lines).

Relevant mechanisms:

| Mechanism | Where | Takeaway |
|---|---|---|
| One request per process, JSON stdin/stdout | `src/backend.cpp:222-276` | Fits Myuzik's low idle-RAM goal; no daemon |
| 45 s watchdog (75 s for playback); `setsid`; process-group kill | `src/backend.cpp:236-276` | Cancellation must kill the whole helper tree |
| `ytmusicapi` search and browse | `helper/catalog.py:402-470` | Mature catalog layer; anonymous use |
| `yt-dlp` resolve and buffer | `helper/catalog.py:366-400` | Use `download=False` for URL, `download=True` for a file |
| Buffer whole song, max 32 MiB, then play local file | `src/backend.cpp:680-780` | Avoids expiring URLs, headers and range fragility |
| Format choice: Opus/WebM, m4a fallback, data saver cap | `helper/catalog.py:330-350` | Good default for GStreamer |
| Preload next track into a temp dir | `src/backend.cpp:2117` | Deferred to M3 |
| Cookies: optional Netscape file, never browser profile | `README.md:215-221` | Keep optional; document sensitivity |
| Lyrics: YouTube first, then exact LRCLIB match | `helper/catalog.py:73-120` | Myuzik already has the stricter LRCLIB matcher |
| Error mapping to sign-in/unavailable/network | `src/backend.cpp:281-292` | Map provider errors, do not leak signed URLs |

License: MIT. Code can be adapted with the copyright/permission notice. This
plan prefers a smaller, fresh helper informed by the design rather than copying

### 2.2 AudioTube (`/tmp/audiotube`, `https://invent.kde.org/multimedia/audiotube`)

AudioTube is a KDE/Qt/Kirigami client for YouTube Music. Its source is
**GPL-2.0-only OR GPL-3.0-only OR LicenseRef-KDE-Accepted-GPL** (see SPDX
headers and `LICENSES/`). **No AudioTube code may be copied into MIT Myuzik.**
Ideas and behaviour are usable.

Relevant mechanisms:

| Mechanism | Where | Takeaway |
|---|---|---|
| Embeds Python via pybind11 in a dedicated `QThread` | `src/ytmusic.cpp:20-70`, `src/asyncytmusic.cpp` | Low latency, but a live Python interpreter costs idle memory; Myuzik uses one-shot instead |
| `ytmusicapi==1.12.3` pinned; `yt-dlp` unpinned | `requirements.txt`, `src/ytmusic.h:15` | Pin both; expose a version/status check |
| `extract_video_info(video_id)` calls `yt_dlp.YoutubeDL.extract_info(download=False)` | `src/ytmusic.cpp:722-737` | Same API Sung uses |
| Picks highest-quality audio-only format, prefers Opus; falls back to worst video | `src/videoinfoextractor.cpp:32-80` | Use an explicit format chain, including a fallback |
| Direct `MediaPlayer.source = audioUrl`; no disk buffer | `src/contents/ui/PlayerFooter.qml:130-160` | Lighter, but jittery seek/expiry; MPRIS `canSeek: false` (`Main.qml:340`) |
| Workaround for `BufferingMedia` + `StoppedState` | `PlayerFooter.qml:145-152` | Confirms direct streaming is fragile |
| LRCLIB `api/get` with title/artist/album/duration | `src/lyricsmodel.cpp:48-80` | Myuzik already does this more strictly |
| Requires QtMultimedia **GStreamer** backend | `README.md` | GStreamer is the right Myuzik engine; no Qt dependency needed |

The key contrast: AudioTube streams the signed URL directly and cannot seek
reliably; Sung buffers and can. Myuzik's overlay follows playback position, so
buffer-first is the better fit.

## 3. Goals and non-goals

### M1 goals

- Search YouTube Music songs and play them.
- Start the selected song's radio/watch playlist and continue it when the queue
  runs out.
- Show cover art and synced LRCLIB lyrics.
- Keep Navidrome behaviour and tests unchanged.
- Work without Navidrome for Search/Play/Lyrics.
- Fail clearly when the helper, Python, Node or network is missing.
- Keep idle RAM within the existing budget (no helper process at idle).
- Keep all network/process work off the UI thread.

### M1 non-goals

- YouTube category/radio browsing pages (M2); the song radio itself is in M1.
- Preloading the next track (M3).
- Cookies import UI (M1 reads an optional config path; UI in M3).
- Audius/Internet Archive providers (later).
- Download/export button, offline library pinning, SponsorBlock.
- Full library routes without Navidrome (M2).
- Replacing Navidrome.

## 4. Architecture

```
Shell (GPUI main thread)
 ├─ YouTubeProvider (background executor)
 │   └─ HelperProcess ──spawn──> python helper/ytmusic.py
 │                               ├─ ytmusicapi (search/browse)
 │                               └─ yt-dlp (resolve/buffer)
 ├─ StreamCache (~/.cache/myuzik/streams)
 ├─ CoverCache (URL-keyed thumbnails)
 ├─ LyricsProvider (optional Navidrome + LRCLIB)
 └─ PlayerHandle ──Load(file://…)──> GStreamer playbin
```

- **UI thread:** state, rendering, spawn/completion only.
- **Background executor:** helper subprocess wait, file I/O, cover download.
- **Player thread:** unchanged; `PlayerCommand::Load` already accepts any URI.
- **Helper:** one process per request; no daemon, no idle memory.
- **Streaming:** helper downloads to a cache directory; GStreamer plays a local
  file. No signed URL reaches the player or logs.

Why not stream the URL directly like AudioTube:

- signed URLs expire; a paused track can fail on resume;
- seeking and duration are less reliable;
- MPRIS position and the lyric overlay need a stable clock;
- HTTP headers/range handling would leak into the player;
- a local file makes replay and later preload trivial.

## 6. Helper protocol

### 6.1 Invocation

- Python resolution order:
  1. `MYUZIK_YT_PYTHON` (tests/advanced);
  2. `~/.local/lib/myuzik/runtime/bin/python` (installed);
  3. `python3` from `PATH`.
- Helper resolution order:
  1. `MYUZIK_YT_HELPER` (tests);
  2. `~/.local/lib/myuzik/ytmusic.py` (installed);
  3. `helper/ytmusic.py` beside the development binary.
- One JSON object on stdin, one JSON object on stdout, then exit.
- `{"ok": true, ...}` on success; `{"ok": false, "error": "..."}` on failure.
  The wrapper adds `ok`, as Sung does (`helper/catalog.py:478-486`).
- Input capped at 1 MiB; output capped at 2 MiB.
- stderr is discarded in production (`Stdio::null()`), because `yt-dlp` errors
  may contain signed URLs. `MYUZIK_YT_DEBUG=1` inherits stderr for diagnosis.

### 6.2 Requests

`version` (status/diagnostics):

```json
{"op":"version"}
{"ok":true,"ytmusicapi":"1.12.3","yt_dlp":"2026.08.19","python":"3.14.8"}
```

`search`:

```json
{"op":"search","query":"lofi","limit":20,"filter":"songs"}
{"ok":true,"items":[
  {"videoId":"kAw9xGI8vgk","title":"…","artist":"…","album":"…",
   "seconds":215,"art":"https://…"}
]}
```

`buffer`:

```json
{"op":"buffer","id":"kAw9xGI8vgk","directory":"/home/…/streams/ab12",
 "root":"/home/…/streams","quality":"standard","cookies":"","fallback":false}
{"ok":true,"file":"/home/…/streams/ab12/kAw9xGI8vgk.webm","seconds":215}
```

### 6.3 Helper rules

- Validate `id` with `^[A-Za-z0-9_-]{11}$`.
- Resolve `directory` and `root`; require `directory` to be inside `root`;
  create it with mode 0700; delete only regular files inside it.
- `yt-dlp` options: `quiet`, `noprogress`, `no_warnings`, `noplaylist`,
  `socket_timeout=18`, `retries=2`, `extractor_retries=2`, `cachedir=False`,
  `js_runtimes={"node": {}}`.
- Format chain:
  - standard: `bestaudio[ext=webm]` → `bestaudio[ext=m4a]` → `bestaudio`;
  - saver: the same with `[abr<=80]`, then `worstaudio`.
  - `fallback=true` swaps the container order (m4a first).
- `buffer`: `max_filesize=32 MiB` plus a progress hook that raises if
  `downloaded_bytes > 32 MiB`; `outtmpl=directory/<id>.%(ext)s`; return the
  prepared filename.
- `extract_info("https://music.youtube.com/watch?v=" + id, download=True)`.
- `search`: `YTMusic(requests_session=True)`, request timeout 20 s (8 s for
  lyrics), `limit` clamped 1..50, filter `songs` for M1. Drop items without a
  video id; drop `isAvailable == false`; dedupe by video id.
- Thumbnail: use the last thumbnail; rewrite `googleusercontent.com` /
  `ggpht.com` size suffix to `=w544-h544-l90-rj` as Sung does
  (`helper/catalog.py:9-22`).
- Parse `duration_seconds`, falling back to `duration` (`m:ss` / `h:mm:ss`).
- Return errors as one line, max ~1,800 chars, with URLs redacted.

### 6.4 Version pinning

`helper/requirements.txt`:

```
ytmusicapi==1.12.3
yt-dlp[default]==2026.8.19
```

Both versions were verified on this machine (Python 3.14.8, Node v25.9.0,
GStreamer 1.28.7). The helper reports both versions; Settings shows a warning
when they differ from the pinned values.

## 7. Rust process management

New `src/provider/process.rs` (or private module inside `youtube.rs`):

```rust
fn call_helper(
    req: &serde_json::Value,
    timeout: Duration,
    cancel: &AtomicBool,
) -> Result<serde_json::Value, ProviderError>
```

- `Command::new(&python).arg(&helper)`, `stdin/stdout` piped, `stderr` null.
- `pre_exec` (unsafe, Linux):
  - `setsid()` so the helper and any children share a process group;
  - `prctl(PR_SET_PDEATHSIG, SIGKILL)` so the helper dies with Myuzik.
- Write the request, close stdin.
- Poll `try_wait()` every 25 ms; on timeout or `cancel`, `kill(-pid, SIGKILL)`,
  `wait()`, and return `Timeout`/`Cancelled`.
- Read stdout only after exit; cap at 2 MiB.
- Parse `ok`; map `ok:false` to `ProviderError::Unavailable` (string).
- No shell, no string interpolation into a command line.

Timeouts:

| Operation | Timeout |
|---|---|
| `version` | 10 s |
| `search` | 30 s |
| `buffer` | 120 s |

## 8. Search integration

Current problem: `Shell::schedule_search()` returns immediately when a local
library index exists (`src/ui/shell.rs:1336-1356`), so no remote source is ever
queried after the first sync. M1 restructures it:

1. On every keystroke, update local results immediately from
   `library_index` (if any) and keep existing Navidrome behaviour when the index
   is empty.
2. If `youtube_enabled` and the query is non-empty, debounce 350 ms, cancel the
   previous YouTube call, and start one helper `search`.
3. One generation counter covers both Navidrome and YouTube completions. A
   completion whose generation is stale is dropped.
4. Merge fields instead of replacing the whole `SearchResults`:
   - local/Navidrome completion sets artists/albums/songs/playlists and leaves
     `youtube` intact;
   - YouTube completion sets `youtube` and leaves the rest intact.
5. Clear everything when the query is empty or the route leaves Search.

Result hygiene:

- `filter="songs"` only in M1.
- Drop durations above 20 minutes (long mixes/podcasts); make the cap a constant
  for now, configurable later.
- Dedupe by `videoId`.
- Keep at most 20 items.
- In-memory cache `query -> (Instant, Vec<Track>)`, TTL 60 s, one entry per
  query, bounded to 32 entries.

UI (`src/ui/shell.rs` Search branch, around 3771-3960):

- Add a **YOUTUBE MUSIC** section label above its rows.
- Row text: `title — artist` and duration on the right; source label is the
  section, not a repeated badge.
- Add focus handles `search-youtube-{i}`, `Role::Button`,
  `aria_label("Play {title} by {artist} on YouTube Music")`.
- Add an activation branch for `search-youtube-` in `activate_focused`
  (around `src/ui/shell.rs:786-825`).
- Loading: one subtle row, "Searching YouTube Music…" while the helper runs.
- Error: one inline row with the mapped message and a "Retry" action. Do not
  toast on every keystroke.
- Empty: existing "No results" check adds `results.youtube.is_empty()`.

## 9. Playback integration

### 9.1 Dispatch

`Shell::load_and_play()` branches on `track.source`:

- `Navidrome`: existing `client.stream_url()` path; unchanged.
- `YouTube`: `play_youtube(track, cx)`; no Navidrome client required.
- `Navidrome` with no client: toast "Connect a music server to play this track."

### 9.2 `play_youtube`

1. Cancel the previous buffer token; increment `youtube_generation`.
2. `player_state.set_status(PlaybackStatus::Buffering)` and notify.
3. Spawn on the background executor:
   - `provider.buffer(track, cancel)`.
4. On completion, if generation is current and `player_state.current.id` still
   matches:
   - `PlayerCommand::Load { uri: file://…, track_id }`;
   - `PlayerCommand::Play`;
   - store the buffered path for cleanup/MPRIS.
5. On error, if current: `player_state.set_status(PlaybackStatus::Stopped)` and
   toast the mapped error. If the track changed, drop silently.
6. On `TrackStarted`, existing event loop handles lyrics/MPRIS/scrobble.

### 9.3 Cache layout

```
~/.cache/myuzik/streams/
  <sha256("yt:"+videoId)>/
    <videoId>.webm
```

- One directory per track, 0700.
- Before writing, clear regular files in that directory.
- `StreamCache::prune(max_bytes)` on startup and after each successful buffer:
  remove oldest directories until under the bound (default 1 GiB).
- A cached file is reusable only when the helper reports the same quality;
  include quality in the directory key: `<hash>-<quality>`.
- Corrupt/unplayable file: delete it and retry once with `fallback=true`; then
  show an error.

### 9.4 Seeking, duration, EOS

- GStreamer seeks a local file normally; no URL/header work.
- Duration comes from the helper (`seconds`) and is confirmed by the engine.
- EOS uses the existing `play_next` path. M1 accepts a short buffering gap
  between YouTube tracks; M3 preloads the next track.

### 9.5 Cancellation

- `Shell` owns `youtube_search_cancel` and `youtube_buffer_cancel`
  (`Arc<AtomicBool>`).
- Typing cancels the previous search; changing track cancels the previous
  buffer; closing the app sets both.
- Helper process groups are killed, so skipping a track does not keep
  downloading 30 MiB in the background.

## 10. Cover art

- Add `Track::cover_key()`:
  - Navidrome: `cover_art_id`;
  - YouTube: `"yt-" + sha256(cover_url)` (hex, safe as a filename).
- `cache_track_cover()`:
  - if `cover_url` is present, fetch it with `ureq` (connect 8 s, recv 15 s,
    global 25 s; max 5 MiB; `Accept: image/jpeg,image/png`);
  - reject non-`http(s)` URLs;
  - if the bytes are not PNG/JPEG, decode with the `image` crate and re-encode
    PNG (YouTube may return WebP);
  - write through `CoverCache::write`, which already does atomic writes and
    pruning.
- Use `cover_key()` in the cover cache, MPRIS art lookup and overlay.
- The `TrackStarted` MPRIS update must not overwrite a YouTube cover with
  `None`: either compute the cached path from `cover_key()` or skip the update
  until `cache_track_cover` finishes.

## 11. Lyrics

- Add `LyricsProvider::with_optional_client(client: Option<NavidromeClient>, …)`
  and keep `new(client, …)` as a thin wrapper so existing tests compile.
- `fetch()`:
  - Navidrome step only when `client.is_some()` and
    `track.source == TrackSource::Navidrome`;
  - LRCLIB remains for every source.
- YouTube titles often carry suffixes. Add a small normaliser used only for the
  LRCLIB lookup (not display): strip `(Official Video)`, `[Official Audio]`,
  `(Lyrics)`, `(Visualizer)`, `(Audio)`, `(Remastered …)` and trailing
  `feat. …`/`ft. …`; collapse whitespace. Keep the existing strict
  title/artist/duration checks.
- `LyricsCache::key()` is metadata-based, so no schema change; YouTube tracks
  reuse it.
- Keep the existing generation guard and overlay update path.

## 12. MPRIS, scrobble, radio, queue

- MPRIS metadata: `metadata_for()` already uses title/artist/album/duration;
  pass the cached cover path. Position/seek work because playback is local.
- Scrobble: in the `TrackStarted` branch (`src/ui/shell.rs:528-570`) and the
  periodic submit branch (`~394-408`), skip when the current track source is
  YouTube. Do not send a `yt:` id to Navidrome.
- Radio: `ensure_radio()` has a YouTube branch that fetches
  `get_watch_playlist(videoId=seed, radio=True)` and appends unique tracks. The
  first radio batch is fetched immediately after a search result is clicked; a
  queue that runs out fetches another batch and resumes on its first track.
- Queue: `Track` clones carry source/cover URL; mixing sources is allowed.
  `Queue::ids()` remains id-based and unique thanks to the `yt:` prefix.

## 13. Running without Navidrome

- `Shell::new` route:
  - client present → `Home`;
  - no client, `youtube_enabled` → `Search`;
  - otherwise → `Setup`.
- Setup screen gets a secondary action: **Use YouTube Music instead**. It sets
  `youtube_enabled = true`, saves the config, and opens Search.
- Settings Account section shows "Not connected" and a **Connect Navidrome**
  action that opens Setup.
- `LyricsProvider` is always constructed (with `None` when there is no client),
  so lyrics work for YouTube.
- Library routes without a client render the existing empty/connect states;
  `sync_library` already shows "Connect a server first."
- `ensure_radio`, star/playlist actions and album/artist/playlist openers
  already guard `Option<client>`; audit them and add a toast where a click
  currently does nothing.
- The initial route must focus the search field so the app is usable
  immediately.

This is intentionally narrower than M2: Home/Albums/Artists/Playlists/Favorites
remain Navidrome-only until browse support lands.

## 16. Security and legal guardrails

- No shell invocation; only `Command::new(python).arg(helper)`.
- Validate the 11-character video id and the cache directory root.
- Helper has its own process group and dies with the parent.
- Max request/response sizes; max download 32 MiB; max cover 5 MiB.
- Cookie file is user-selected, never copied, never logged; document 0600.
- No download/export UI; buffered files are an implementation detail and are
  pruned.

    contributors."
  - `ytmusicapi` MIT; `yt-dlp` Unlicense.

## 17. Testing

### 17.1 Offline unit tests

- `Track` serde: old JSON without `source`/`cover_url` loads as Navidrome;
  YouTube round-trips.
- Video id validation: good 11-char ids; reject empty, 10/12 chars, `/`, `..`,
  newline, shell metacharacters.

## 22. Risks and mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| YouTube changes break `yt-dlp` | High over time | Pin a known version, show update command, map errors, keep Navidrome usable |
| `ytmusicapi` changes break search | Medium | Pin 1.12.3; version check; helper is isolated and replaceable |
| Helper/Python/Node missing | Medium | Status row, actionable install errors, core app still runs |
| Buffer start delay | Medium | Show Buffering, 32 MiB cap, preload in M3 |
| Disk growth | Low | 1 GiB LRU prune, `--purge` cleanup |
| Signed URL/cookie leak | Low | stderr null, redact errors, 0600 cookie, never log URL |
| ToS/legal complaint | Medium | Personal use, no download UI, docs disclaimer, no redistribution |
| Test breakage from `Track` fields | High (mechanical) | Phase 1 checklist + `grep` audit |
| No-Navidrome route regressions | Medium | Route/a11y tests, guarded client use, explicit empty states |

## 23. Rollout and rollback

- `youtube_enabled` is the kill switch: off means no helper spawn, no YouTube
  section, and the app behaves exactly as before.
- The helper is optional; removing it degrades to a clear error, not a crash.
- `Track`/`SearchResults` changes are additive with serde defaults; old caches
  still load.
- No config version bump; rollback to an older binary ignores the new keys via
  the existing `unknown` map (they are preserved, not destroyed).
- If YouTube support must be removed, delete `src/provider/`, the helper, the
  Search section and the Settings rows; Navidrome is untouched.

## 26. Open decisions (resolved for M1)

- **Buffer vs direct stream:** buffer. Direct streaming like AudioTube cannot
  seek reliably and makes the overlay/MPRIS position fragile.
- **Persistent vs one-shot Python:** one-shot. Persistent embedding costs idle
  RAM; Myuzik's budget is a core requirement.
- **Trait vs concrete provider:** concrete. Add the trait with the second
  provider.
- **Navidrome:** keep; M1 adds YouTube alongside it, with a no-Navidrome path
  for Search/Play/Lyrics.
- **Cookies:** optional config path in M1; UI later.
- **Track fields:** `source` + `cover_url`; video id is parsed from the `yt:`
  prefix.
